# Kennari: 5/3/1 Program Spec
### Companion to KENNARI-PRD.md | For use with Claude Code

Kennari supports more than one training program. The original program is **Lite Viking** (KENNARI-PRD.md). This file specs the second program, **5/3/1**, based on Jim Wendler's book. Same app, same login, same design system, same workout screen. Only the program logic, setup and a few workout-screen states differ.

Core promise is unchanged: zero thinking. The user opens the app and it tells them exactly what to lift today, how much, and how many reps.

---

## 1. Rules for building this

- **Do not break Lite Viking.** Every Lite Viking read and write stays scoped to `program = 'lite_viking'`. A user on Lite Viking must see no change.
- **Additive database changes only.** New columns with defaults, new tables. No renames, no drops.
- **Reuse before building.** Use the existing workout screen, weight display (total / per side / per dumbbell), lbs/kg handling, rounding (`roundToNearest`), rest timer and set dots. Add states, do not fork screens.
- **Keep 5/3/1 logic in its own file:** `program531.js`. Leave `program.js` as the Lite Viking engine.
- All weights stored in lbs, converted at display time, rounded with the app's existing rules.

---

## 2. Program choice

- The program is chosen **once**, during onboarding, and stored on `profiles.active_program` (`'lite_viking'` or `'531'`).
- After login, the app goes straight to the user's program. No picker on every open.
- Switching program in Settings is **out of scope** for now.
- Existing users default to `'lite_viking'`.

---

## 3. The method

### 3.1 Lifts and rotation
- 4 main lifts, **one per workout**, always in this order: **Press, Deadlift, Bench, Squat.** Exercise keys match Lite Viking: `press`, `deadlift`, `bench`, `squat`.
- No calendar. The app always serves the next workout in the sequence, no matter how many days have passed.
- Days per week is not asked. 3 or 4 days per week produce the same sequence.

### 3.2 Test days (setup)
Before the program starts, each lift is tested once, **one lift per workout**, in rotation order. The app tracks which tests are done and always serves the next untested lift.

Test workout for a lift:
1. User enters a **test weight**: a weight they can lift about 5 times (in their display unit, stored in lbs).
2. Warmup: 40% x5, 50% x5, 60% x3 **of the test weight**.
3. Test set: test weight, **as many reps as possible**. User enters the reps achieved.
4. App calculates and stores:
   - Estimated 1RM = `weight x reps x 0.0333 + weight`
   - Training max (TM) = 90% of estimated 1RM, rounded with the app's rounding rule

After the 4th test, the next workout is the first regular workout (Cycle 1, Week 1, Press).

### 3.3 Regular workouts
Every percentage is of that lift's **training max**, never the real max.

Warmup (every workout): 40% x5, 50% x5, 60% x3.

Work sets by week:

| Week | Label | Set 1 | Set 2 | Set 3 |
|------|-------|-------|-------|-------|
| 1 | 5s | 65% x5 | 75% x5 | 85% x5+ |
| 2 | 3s | 70% x3 | 80% x3 | 90% x3+ |
| 3 | 5/3/1 | 75% x5 | 85% x3 | 95% x1+ |
| 4 | Deload | 40% x5 | 50% x5 | 60% x5 |

- `+` = **AMRAP set** (as many reps as possible). Target shown as the minimum (e.g. "5+"). User enters actual reps achieved; stored in `sets.reps_completed`.
- Deload week has no AMRAP set; all sets are fixed reps.
- Main lift only. No assistance exercises.

### 3.4 Position and progression (derived, no extra state)
Let `n` = number of **completed regular 5/3/1 workouts** for the user (test days not counted).

- `lift  = ['press','deadlift','bench','squat'][n % 4]`
- `week  = Math.floor((n % 16) / 4) + 1`   (1 to 4)
- `cycle = Math.floor(n / 16) + 1`          (1, 2, 3...)
- Current TM for a lift = starting TM + (cycle - 1) x increment
  - Increment: **+5 lbs** for press and bench, **+10 lbs** for squat and deadlift

A workout that is started but not completed does not advance `n`.

## 4. Data model (additive)

```sql
-- Program on profile (chosen once at onboarding)
ALTER TABLE profiles
  ADD COLUMN IF NOT EXISTS active_program text NOT NULL DEFAULT 'lite_viking';

-- Program tag on sessions; existing rows become lite_viking
ALTER TABLE sessions
  ADD COLUMN IF NOT EXISTS program text NOT NULL DEFAULT 'lite_viking';

-- Marks 5/3/1 test-day sessions (not counted in n)
ALTER TABLE sessions
  ADD COLUMN IF NOT EXISTS is_test boolean NOT NULL DEFAULT false;

-- 5/3/1 training maxes, one row per lift per test
CREATE TABLE IF NOT EXISTS training_maxes (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  lift text NOT NULL,                 -- press | deadlift | bench | squat
  test_weight_lbs numeric NOT NULL,
  test_reps integer NOT NULL,
  e1rm_lbs numeric NOT NULL,
  training_max_lbs numeric NOT NULL,  -- starting TM for this lift
  created_at timestamptz NOT NULL DEFAULT now()
);
-- RLS: same pattern as other user tables (user can read/write own rows only)
```

For 5/3/1 sessions:
- `sessions.program = '531'`
- `sessions.workout_day` = the lift key (e.g. `'press'`)
- `sets.set_type` = `'warmup'` or `'working'`; the AMRAP set is the last working set and stores actual reps in `reps_completed`
- 5/3/1 never reads or writes `starting_weights` (Lite Viking only)

If a lift has several `training_maxes` rows, the latest one is the starting TM (allows a re-test later).

## 5. Engine: `program531.js`

Pure logic plus Supabase reads. Suggested exports:

- `estimate1RM(weightLbs, reps)`
- `trainingMaxFrom1RM(e1rmLbs)`
- `get531Position(userId)` returns `{ phase: 'test' | 'program', lift, week, cycle, n }` (phase is `'test'` until all 4 lifts have a training max)
- `getCurrentTM(userId, lift, cycle)`
- `get531Workout(userId)` returns:
  ```
  {
    program: '531',
    kind: 'test' | 'program',
    lift: 'press',
    label: 'TEST · PRESS' | 'WEEK 1 · 5s · PRESS',
    needsTestWeight: true | false,
    warmupSets: [{ setNumber, reps, weightLbs }],
    workingSets: [{ setNumber, reps, weightLbs, amrap: true|false }]
  }
  ```
  For a test workout, warmup and the single test set are calculated after the user enters the test weight.
- `save531Test(userId, lift, testWeightLbs, reps)` writes `training_maxes`

## 6. Screens (what changes)

- **Onboarding:** new first question: which program (Lite Viking / 5/3/1), with a one-line description of each. Saves `active_program`. If 5/3/1: skip the starting-weights step (tests replace it). Keep name, age, bodyweight, barbell weight, goals.
- **Home:** reads `active_program`. For 5/3/1 shows today's label (e.g. "TEST · PRESS" or "WEEK 2 · 3s · BENCH") and the single lift.
- **Workout screen, 5/3/1 states:**
  - Test day: before warmup, a test-weight input in the same bottom-card style as the weight adjustment popup; then warmup; then the test set as AMRAP.
  - AMRAP set: label shows "5+ REPS"; on Complete Set, a reps input (large +/- stepper, prefilled with the target) before the rest timer; saves `reps_completed`.
  - Dots: 3 warmup, 3 working (1 on test days).
  - Header label uses `label` from `get531Workout`.
- **Tracking:** unchanged for now.
